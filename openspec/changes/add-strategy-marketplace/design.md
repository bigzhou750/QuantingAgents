## Context

现有策略服务面向用户自定义策略，集合为 `strategy_definitions`，已有术语过滤和用户隔离。策略广场需要区分“平台模板”和“用户策略实例”，不能把模板直接混成某个用户的数据。

## Goals / Non-Goals

**Goals:**

- 建立平台策略模板与用户策略实例的边界。
- 支持策略广场卡片、详情、筛选和加入我的策略。
- 保持策略说明适合新手阅读，并复用现有合规过滤。

**Non-Goals:**

- 不在本 change 中实现历史模拟计算引擎。
- 不自动从互联网抓取并发布策略。
- 不改变用户自定义策略的基本 CRUD 语义。

## Decisions

1. 平台模板与用户策略实例分表或用明确类型隔离
   - 理由：模板是公共资产，用户策略是私有数据，权限和生命周期不同。
   - 替代方案：全部放入 `strategy_definitions`，会增加查询隔离和上架状态复杂度。

2. 加入我的策略采用复制实例
   - 理由：用户加入后可能调整参数，应与平台模板后续改版解耦。
   - 替代方案：仅保存引用，难以支持用户个性化调整和版本追踪。

3. 策略模板上架需要状态机
   - 理由：来源可能包括人工录入、运营沉淀、Agent 草案，必须经过合规和结构化检查。
   - 替代方案：创建即上架，风险过高。

## Risks / Trade-offs

- [Risk] 策略卡片指标依赖后续历史模拟 change → Mitigation：本 change 允许展示“数据准备中”，不伪造指标。
- [Risk] 模板复制后平台模板更新无法自动同步 → Mitigation：保留 `source_template_id` 和 `source_version`，后续提示用户可升级。
- [Risk] 新手解释与专业准确性冲突 → Mitigation：卡片做白话解释，详情保留结构化规则和展开指标。

## Migration Plan

- 新增平台策略模板数据结构和初始种子数据。
- 新增策略广场 API 和前端页面。
- 在加入我的策略时创建用户策略实例。
- 回滚时隐藏策略广场入口，不影响已有用户策略实例。
