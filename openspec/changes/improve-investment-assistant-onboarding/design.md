## Context

See proposal.md - Why.

当前项目已经有个人投资助手、Agent 评测、自然语言研究和股票分析相关路由，但侧边栏菜单是手写的，且存在路由项格式异常的问题。个人投资助手页面本身也偏“功能完整但入口直接”，对新手来说缺少默认模板、策略选择向导、任务向导和结果解释的连续路径。

## Goals / Non-Goals

**Goals:**

- 让个人投资助手和 Agent 评测在侧边栏中稳定可发现、可点击。
- 让首次进入个人投资助手的新手能快速开始，而不是面对空配置页。
- 让选股、体检、策略选择和后续验证形成更顺手的操作路径。
- 复用已有 `/investment`、`/evaluation`、`PersonalInvestment/*` 和现有任务结果页。

**Non-Goals:**

- 不引入新的全局导航系统或自动生成菜单机制。
- 不改变画像、策略、筛选、体检的底层数据模型。
- 不增加权限控制、计费或多租户逻辑。
- 不实现完整复盘引擎或观察池的数据仓库，只做可进入的入口与轻量动作。
- 不实现“保证赚钱”的承诺页，也不把回测结果包装成收益保证。

## Decisions

### 1. 直接修复手写侧边栏，而不是重构为动态路由菜单

菜单由 `SidebarMenu.vue` 直接维护，最小风险方案是补充缺失入口并修正异常标记。这样能把“入口不可见”这个 bug 快速修掉，同时避免一次性改动整个布局框架。

**Alternative considered:** 让侧边栏完全按路由 meta 自动生成。该方案更一致，但会牵动当前菜单分组、图标和子菜单组织，不适合作为本次修复的首选。

### 2. 以现有个人投资助手页面作为新手引导载体

新手引导、默认模板和任务向导直接挂在现有 `/investment/profile`、`/investment/strategies` 和结果页上，不新增独立的 onboarding 页面。

**Rationale:** 用户已经有这些页面的入口和路由，直接增强现有页面比新增独立流程更稳。

### 3. 默认模板优先用“可编辑表单预填”而不是独立模板管理系统

首版只需要保守/平衡/进取等基础模板预填，不需要把模板做成单独的可维护资产。模板本质上是降低首填成本的入口，不是核心业务对象。

**Alternative considered:** 新建模板中心。该方案扩展性更强，但会增加模型、API 和维护复杂度，首版没有必要。

### 4. 结果页优化以“解释 + 下一步动作”为主

选股和体检页保留现有数据表和摘要，但要强化三个动作：查看原因、加入观察、进入复盘。这样能把一次性结果转成持续流程。

### 5. 新增策略选择向导，但不做“自动荐股”

向导先回答“我适合什么策略类型”，再进入具体策略管理。它输出的是策略画像匹配建议、适用场景和证据层级，而不是股票推荐列表。

**Rationale:** 新手最大的难点通常不是“跑哪个按钮”，而是“不知道该从哪类策略开始”。把策略选择和股票筛选拆开，能避免用户把策略名称误解成交易信号。

### 6. 可靠性验证按证据分层，而不是单点胜负

现有 runtime 能力可以支持筛选、体检、回测和风险拆解，但产品层不能把单次回测或单次市场适配说成稳定盈利。可靠性展示应分成：

```
画像适配 -> 策略类型匹配 -> 当前市场体检 -> 历史回测证据 -> 风险拆解
```

如果后续要增强可信度，优先复用 `query_strategies`、`get_strategy_evidence`、`backtest`、`portfolio_risk_xray`、`create_hypothesis` 和 `link_backtest`，由 VibeAgent 负责编排，而不是在前端手工拼逻辑。

### 7. 观察和复盘先做入口，不做重资产建模

本次只保证用户能从结果页跳到观察或复盘语义，暂不要求独立的观察池存储结构或完整复盘数据模型。

**Rationale:** 先验证用户是否需要持续跟踪，再决定是否扩展成单独模块。

## Risks / Trade-offs

- [侧边栏手写项遗漏新入口] → 在本次 change 中显式补充 `/investment` 和 `/evaluation` 的菜单项，并加入菜单渲染测试。
- [默认模板与真实画像混淆] → 模板只作为表单预填，不作为独立持久化对象。
- [新手把策略理解成荐股] → 策略选择页必须显示适用人群、适用市场、证据层级和失效条件。
- [结果页仍然偏技术化] → 通过文案和按钮动作把“候选/观察/复盘”前置，减少用户只看到表格的感觉。
- [观察/复盘只做入口不做闭环] → 明确本次不承诺完整复盘引擎，避免 scope 膨胀。
- [验证能力不足以证明盈利] → 只展示证据强弱和可复核来源，不输出“能赚钱”的结论。

## Migration Plan

1. 先修侧边栏菜单和路由跳转，保证入口可见且可达。
2. 在个人投资助手页面补默认模板和任务引导。
3. 在策略选择页补策略类型解释和新手匹配向导。
4. 在选股、体检和验证结果页补“下一步”动作与证据层级说明。
5. 再补观察与复盘入口的最小路径。
6. 通过前端交互测试确认菜单、引导、证据说明和跳转行为。
7. 若某一部分引导样式或入口路径不稳定，先保留现有页面功能，只回滚新引导组件和文案，不回滚数据模型。

## Open Questions

- 观察池是否需要立即持久化，还是先用已有自选股/结果页作为过渡入口，可以在实现前再定。
- 默认模板是否需要按市场区分（A股/港股/美股），首版可以先用通用模板。
- 策略选择向导首版是做“规则模板归类”，还是直接对接 strategy discovery 的证据查询结果，取决于后续 change 的边界。
