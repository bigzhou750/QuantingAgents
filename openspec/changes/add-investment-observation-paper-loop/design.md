## Context

现有系统有自选股、策略选股结果、新闻关注、分析报告和模拟交易，但缺少一个保存“为什么关注这个标的”的中间层。模拟交易已有 `analysis_id` 可选字段，但缺少策略候选来源追踪。

## Goals / Non-Goals

**Goals:**

- 新增观察记录作为策略结果的持久化承接层。
- 打通观察到单股分析、新闻影响、模拟交易和复盘。
- 扩展模拟交易来源追踪，保持现有下单接口兼容。

**Non-Goals:**

- 不自动生成实盘交易建议。
- 不自动替用户提交模拟订单。
- 不替代现有自选股，可逐步融合展示。

## Decisions

1. 新增观察集合而不是直接复用自选股
   - 理由：观察记录需要保存来源策略、任务、命中原因、风险提示、复盘状态，自选股模型较轻。
   - 替代方案：扩展自选股，可能影响已有自选股页面和接口兼容。

2. 模拟交易来源字段保持可选
   - 理由：手动模拟交易和报告来源交易仍需兼容。
   - 替代方案：强制所有订单绑定策略，会破坏现有流程。

3. 移出观察采用状态更新
   - 理由：观察记录承载学习和复盘历史，硬删除会丢失来源链路。
   - 替代方案：直接删除，简单但无法复盘。

## Risks / Trade-offs

- [Risk] 观察、自选股、模拟持仓概念重复 → Mitigation：观察强调“来源和学习过程”，自选股强调轻量收藏，模拟持仓强调虚拟交易。
- [Risk] 来源字段扩展影响模拟交易兼容性 → Mitigation：所有新增来源字段可选，旧请求保持可用。
- [Risk] 复盘提醒过多 → Mitigation：只展示待复盘汇总，允许关闭或延后。

## Migration Plan

- 新增观察 API 和页面，不迁移现有自选股。
- 选股结果增加“加入观察”动作。
- 模拟交易扩展可选来源字段。
- 回滚时隐藏观察入口，现有模拟交易和自选股不受影响。
