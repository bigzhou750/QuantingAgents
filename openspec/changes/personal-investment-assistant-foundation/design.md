## Context

See proposal.md - Why.

当前仓库已经有用户体系、自选股、模拟交易、自然语言研究工作台和任务中心，但缺少一个统一的“个人投资上下文”层。VibeAgent 目前接收的是纯文本问题和少量任务元数据，无法稳定表达用户画像、持仓约束和策略偏好。

## Goals / Non-Goals

**Goals:**

- 让用户在一个稳定页面中维护投资画像与策略定义。
- 让策略选股和策略体检走统一任务链路，并可追溯、可复盘。
- 让 VibeAgent 研究输入可选择性携带用户画像摘要。
- 复用现有 MongoDB、FastAPI、Vue 3、任务中心和 VibeAgent runtime，不引入新的核心执行平台。

**Non-Goals:**

- 不实现完整历史回测平台、参数寻优或因子研究平台。
- 不接入券商实盘交易或自动下单。
- 不做会员订阅、计费或多租户配额体系。
- 不把策略结果包装成买入/卖出建议。

## Decisions

### 1. 采用“画像 + 策略 + 任务结果”三层模型

个人投资信息分成三类持久化对象：用户画像、策略定义、任务结果。画像表达用户约束，策略定义表达可复用规则，任务结果表达一次运行的候选池或体检结论。

**Rationale:** 这样可以避免把“用户偏好”和“策略规则”混在一个文档里，后续更容易做多个画像、多个策略和复盘。

**Alternative considered:** 直接扩展 `users.preferences` 或自选股文档。该方案落地快，但会把配置、约束和结果混在一起，后续不可维护，因此不采用。

### 2. 策略选股与策略体检先做轻量任务，不把完整回测作为首版

首版的“策略体检”只输出适配度、近期表现摘要和风险说明，不承诺完整回测收益。完整回测保留为后续独立能力。

**Rationale:** 新手产品需要先解决“现在该不该关注这个策略”，而不是一开始就承诺一套高复杂度回测平台。

**Alternative considered:** 直接复用或暴露完整回测引擎给前端。该方案功能强，但参数多、成本高、误用风险大，不适合作为首版门面。

### 3. 研究上下文以受控摘要方式进入 VibeAgent

VibeAgent 入口维持当前自然语言工作台体验，但后端在组装任务时额外生成标准化上下文摘要，包含画像要点、当前策略和持仓约束。原始自由文本不直接拼接到运行时的系统级字段。

**Rationale:** 这样既能个性化，又能避免把不可控的用户输入当成高优先级系统提示。

**Alternative considered:** 让前端把个人信息直接传给 runtime。该方案实现简单，但容易造成数据污染和提示注入风险，因此不采用。

### 4. 结果存储采用独立集合，保留历史审计

新增的画像、策略、筛选任务、体检任务和结果都使用独立集合存储，查询侧按用户 ID 聚合。任务状态与结果摘要需要可单独查看。

**Rationale:** 独立集合便于审计、迁移和回放，也方便后续导出和复盘。

### 5. 前端以“工作台 + 管理页”组织，而不是散落在各处

个人投资助手相关入口统一放在一个可见区域：画像管理、策略管理、策略筛选、策略体检和结果列表。研究工作台只负责消费这些上下文。

**Rationale:** 新手更容易建立心智模型，也减少在多个页面间切换的成本。

## Risks / Trade-offs

- [策略结果被误读为荐股] → 页面和 API 响应统一使用“候选、观察、风险提示、适配度”术语，并禁用买卖指令式措辞。
- [轻量体检被误当成完整回测] → 明确区分“体检”和“回测”，首版只展示适配度摘要，不输出收益承诺。
- [用户画像内容过于自由] → 画像字段采用结构化模型，并对自由文本备注做长度和格式限制。
- [VibeAgent 上下文污染] → 只传归一化摘要，保留原始值在审计或原文记录中，不直接进入系统级 prompt。
- [后续回测扩展时需要重构] → 任务和结果模型预留策略 ID、市场、数据日期和执行摘要字段，便于后续接入完整回测而不迁移主数据结构。

## Migration Plan

1. 新增画像、策略、任务结果的数据模型和集合。
2. 新增后端 API 与服务层，先完成 CRUD 和任务结果持久化。
3. 新增前端管理页和任务入口，接通列表、编辑和详情查看。
4. 将 VibeAgent 任务组装逻辑改为可选注入画像摘要。
5. 为策略筛选和策略体检建立最小可运行任务链路。
6. 补充单元测试、接口测试和前端交互测试。
7. 若验证不通过，回滚顺序为：先关前端入口，再停用新任务类型，最后保留只读历史数据不删除。

## Open Questions

- 策略体检首版采用哪些固定指标最合适，需要结合你希望面向的新手程度再定。
- 是否需要给用户提供多个画像档案，例如“保守 / 平衡 / 激进”三套模板，可以在任务开始前再决定。
