## Context

仓库当前同时包含 FastAPI 后端、Vue 前端、`tradingagents/` 核心分析库和 `vibe_agent_runtime/` Agent 运行时。品牌、配置、日志、容器、提示词、部署文档和测试夹具存在跨目录命名耦合；同时许可证和第三方归属不能因产品品牌迁移被删除。详见 `proposal.md` 及三个 capability spec。

## Goals / Non-Goals

**Goals:**

- 建立“智能投研助手 / zhitouagent”的单一产品身份和内部命名策略。
- 保留现有分析、研究、Agent、工具、提示词、认证和外部接口能力。
- 让未登录用户可验证产品定位、价格、支持方式、隐私政策、服务条款和风险披露。
- 将旧项目宣传信息、旧联系方式、旧仓库入口和敏感开发数据从发布表面清除。
- 以独立第三方声明材料保留必要的法律归属，并用自动扫描防止回归。

**Non-Goals:**

- 不重写投资分析算法、模型适配器、数据源协议或 Agent 决策逻辑。
- 不删除第三方许可证、版权声明、NOTICE 或供应商官方文档链接。
- 不把真实的第三方衍生代码改写为虚假原创声明。
- 不改变用户权限模型、计费计算逻辑、已有业务 API 的字段契约或核心数据库 schema。
- 不在本 change 中决定正式域名、支付服务商或外部客服工单系统。

## Decisions

### 1. 采用“展示身份迁移 + 内部兼容层”

产品展示、默认新建资源和运行时输出统一使用 `zhitouagent`。对仍被现有数据、脚本或调用方使用的旧配置和导入路径，先提供读取兼容或迁移映射，再在稳定发布后逐步弃用。相比一次性物理移动全部目录，这能降低 API、缓存和部署数据的回滚风险。

### 2. 保留核心运行时能力，替换产品可见标识

`vibe_agent_runtime` 的能力、工具和提示词加载链路继续保留；修改产品名、默认路径、User-Agent、帮助文案和运行时元数据。第三方工具内部必须保留的官方来源链接属于依赖归属，不作为产品品牌展示。

### 3. 将公开审核信息放在匿名可访问路由

前端新增或调整公开路由承载产品介绍、定价、隐私政策、服务条款和支持入口；后端仅在需要动态计费数据时提供只读接口。页面不依赖用户登录、不显示密钥配置，也不泄露内部服务拓扑。

### 4. 将旧痕迹治理分为允许、迁移、禁止三类

- **允许**：法律必须保留的许可证、版权、NOTICE 和第三方依赖来源。
- **迁移**：兼容读取用的旧环境变量、数据库集合或历史数据键，写入和对外输出改为新命名。
- **禁止**：产品页面、默认文案、构建产物、部署模板和运行时输出中的旧品牌、旧联系邮箱、旧项目仓库推广链接、上游同步任务和真实敏感数据。

### 5. 采用扫描 + 构建 + 回归三层验收

静态扫描负责身份、邮箱、URL 和敏感信息；构建检查负责前端 dist、Docker context 和部署模板；回归检查负责认证、API、分析任务、事件流、工具/提示词加载和公开路由。仅通过静态替换不能视为完成。

## Risks / Trade-offs

- [Risk] 全量重命名可能破坏内部导入、持久化路径或旧部署。→ 先建立兼容映射和迁移脚本，分阶段切换，并在切换前备份和验证回滚。
- [Risk] 公开隐私政策、服务条款和定价内容如果与实际实现不一致，会增加审核和用户信任风险。→ 以当前真实数据处理和计费行为为准，部署前做页面与接口逐项核对。
- [Risk] 第三方归属过度隐藏可能违反许可证，归属过度外显又会削弱产品独立品牌。→ 将必要归属集中在内部合规材料和适当的法律入口中，不放入营销和默认产品文案。
- [Risk] 扫描规则可能误报第三方依赖链接或测试占位邮箱。→ 使用分层 allowlist，并要求每个例外注明原因、文件范围和是否进入发布包。
- [Risk] 提示词和运行时文案的改名可能影响模型输出格式。→ 对关键提示词做快照回归，验证结构化字段、风险提示和工具调用结果。

## Migration Plan

1. 建立品牌、邮箱、旧 URL、旧命名和许可证例外清单，冻结当前发布基线。
2. 先更新公开页面、默认配置、构建元数据和部署模板，再添加兼容读取与迁移工具。
3. 对 `tradingagents/`、`vibe_agent_runtime/`、`app/` 和 `frontend/` 分模块迁移命名，并逐组执行测试。
4. 清理不再使用的上游同步脚本、旧推广文档、生产日志和敏感文件；将必要许可证归属集中整理。
5. 运行扫描、构建、回归和匿名页面检查，生成发布验收报告。
6. 发布时保留旧配置读取兼容；若核心回归失败，回滚到旧构建并保留迁移前数据目录，修复后重新验证。

## Open Questions

无。正式域名和支付服务商不影响当前规格和任务拆分，可在部署阶段单独配置。
