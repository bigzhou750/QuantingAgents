## Why

平台目前已经有注册登录、数据库用户模型和管理员用户后端接口，但没有面向管理员的完整账号管理控制台，前端也无法查看所有已注册账号、启停账号、分配角色或重置密码。同时现有用户列表接口没有返回 `is_admin`，也缺少安全的账号删除/归档语义，导致“管理员管理账号”只能依赖手工脚本或直接操作数据库。

## What Changes

- 新增管理员专用账号管理页面，路由为 `/settings/users`，仅管理员可访问，提供注册账号列表、关键字搜索、状态筛选、分页和详情查看。
- 新增前端用户管理 API 封装，覆盖管理员创建用户、用户列表、账号状态、角色、重置密码、更新账号信息和安全删除/归档账号。
- 补全后端用户管理接口：用户列表返回 `is_admin`，增加单个用户详情、管理员更新账号资料/配额接口，并为删除账号定义安全的归档语义。
- 删除账号采用“先禁用、后归档”的安全流程：不直接物理删除用户拥有的分析记录、任务、会话和记忆等资源，而是将账号标记为已删除/已归档并断开登录权限；确认无历史资源或管理员显式确认后，可在隔离区保留数据。
- 所有管理员操作沿用现有审计日志机制，记录操作者、目标用户、操作类型和结果，普通用户不能访问这些接口。
- 完善前端权限提示、空状态、加载状态、错误处理和二次确认，覆盖禁用/启用、角色变更、重置密码、删除账号等高风险操作。

## Capabilities

### New Capabilities
- `identity/user-management`: 面向管理员的账号管理能力，覆盖已注册账号的展示、检索、创建、详情、启停、角色分配、密码重置、资料/配额更新和安全删除归档，并保证普通用户无法越权访问。

### Modified Capabilities
- 无。`openspec/specs/` 中尚无对应的用户管理稳定能力，本 change 以新增能力的方式承载，并明确复用 `complete-multi-account-isolation` 中 `identity/multi-account-auth` 的认证和租户隔离契约。

## Impact

- 后端：`app/routers/auth_db.py`、`app/services/user_service.py`、`app/models/user.py`，可能新增归档集合或用户状态字段；现有 `/api/auth/*` 接口保持向后兼容，新增字段为增量，不破坏现有客户端。
- 前端：`frontend/src/api/auth.ts`、`frontend/src/types/auth.ts`、`frontend/src/router/index.ts`、侧边栏菜单和新增的账号管理页面，路由使用现有 `requiresAdmin` 权限守卫。
- 测试：扩展 `tests/test_auth_admin_routes.py`，补充用户列表字段、详情、更新、删除归档、越权、审计和边界场景；前端补充页面组件测试和权限导航测试。
- 运维：删除/归档账号时保留用户所属资源，不产生物理数据丢失；迁移或归档工具只记录状态变更，不触发全量删除。
