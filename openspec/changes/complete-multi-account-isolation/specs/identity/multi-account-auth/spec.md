## Purpose

为平台提供可审计、可撤销且可独立管理的多账号身份能力，使普通用户能够安全注册和使用自己的工作空间，同时保持管理员管理能力与现有登录客户端兼容。

## ADDED Requirements

### Requirement: 用户自主注册
系统 SHALL 提供公开注册接口和前端注册页面；用户名和邮箱 MUST 唯一，密码 MUST 满足最小长度及强度策略，注册成功的账号 MUST 默认是普通、激活但未验证的用户，除非部署配置明确要求邮箱验证后才可登录。

#### Scenario: 注册成功
- **WHEN** 未登录访客提交合法且未占用的用户名、邮箱和密码
- **THEN** 系统创建唯一用户并返回不含密码或密码哈希的用户摘要，且不会自动授予管理员角色

#### Scenario: 重复账号注册
- **WHEN** 用户名或邮箱已被占用
- **THEN** 系统返回明确的 4xx 业务错误，不创建第二个账号，且错误响应不泄露另一账号的额外敏感信息

#### Scenario: 注册输入不合法
- **WHEN** 用户名、邮箱或密码不满足格式、长度或强度要求
- **THEN** 系统拒绝请求并返回字段级校验信息，不写入半成品用户

### Requirement: 身份 Token 生命周期
登录成功 MUST 签发包含用户不可变 ID、Token 类型、签发时间和过期时间的 access/refresh token；系统 MUST 验签、检查过期、检查账号状态，并支持刷新和退出后的撤销。旧的仅以用户名作为唯一身份依据的 Token SHALL 仅在明确兼容窗口内受限接受。

#### Scenario: 有效登录
- **WHEN** 激活用户提交正确密码
- **THEN** 系统返回 access token、refresh token 和用户摘要，并记录成功审计事件

#### Scenario: 无效或已撤销 Token
- **WHEN** 请求携带伪造、过期、类型错误或已撤销的 Token
- **THEN** 受保护接口返回 401，且不得根据客户端提供的 user id 继续处理

#### Scenario: 刷新 Token
- **WHEN** 用户提交有效且未撤销的 refresh token
- **THEN** 系统签发新 token，旧 refresh token 按轮换策略失效，并保留同一用户归属

### Requirement: 账号与管理员操作
用户 MUST 能查看和修改自己的非敏感资料及密码；管理员创建、禁用、启用、重置密码和列举用户的操作 MUST 受管理员权限保护并记录审计日志。普通用户 SHALL 不能提升自己的角色或修改其他用户。

#### Scenario: 普通用户越权管理
- **WHEN** 普通用户调用管理员接口或提交 `is_admin=true`
- **THEN** 系统返回 403，目标账号和角色均不改变

#### Scenario: 禁用账号
- **WHEN** 管理员禁用一个用户
- **THEN** 该用户的新请求、刷新请求和实时连接均被拒绝，且其既有 Token 在状态检查时失效

### Requirement: 认证防护
登录和注册 MUST 具备按 IP、账号和必要时设备维度的限流；密码 MUST 使用单向强哈希存储；认证日志 SHALL 脱敏，不得记录明文密码、完整 Token 或密码哈希。

#### Scenario: 暴力尝试
- **WHEN** 同一账号或来源连续超过配置阈值的失败认证请求
- **THEN** 系统进入限流或短暂锁定并返回统一错误，不影响其他账号正常登录
