## Purpose

建立跨 API、数据库、后台任务和实时通信的一致租户边界，确保任何用户只能访问其身份上下文允许的资源，管理员例外也必须经过明确授权而不能依赖猜测或隐藏参数。

## ADDED Requirements

### Requirement: 统一用户上下文和默认拒绝
所有受保护请求 MUST 从已验证 Token 派生 `user_id` 和角色；资源查询、创建、更新、删除和导出 MUST 使用该上下文。客户端传入的 user id、username、owner_id 或 profile id SHALL 不能覆盖认证上下文。缺少归属证明时系统 MUST 默认拒绝或返回不暴露数据的结果。

#### Scenario: 参数伪造
- **WHEN** 用户 A 请求中携带用户 B 的 user id 或资源 id
- **THEN** 系统按用户 A 查询并返回 403/404，不能返回、修改或删除用户 B 的资源

#### Scenario: 未归属历史数据
- **WHEN** 历史记录没有可验证的 owner
- **THEN** 普通用户不可见；只有受审计的迁移或管理员隔离工具可以处理它

### Requirement: 资源级所有权
所有用户可见的分析任务、报告、自选股、通知、投资记录、观察项、个人配置、操作记录和导入导出文件 MUST 保存规范化 owner，并在每个读写路径执行 owner 条件。管理员跨用户访问 MUST 通过专用授权路径并记录原因。

#### Scenario: 两个账号资源隔离
- **WHEN** 用户 A 和 B 分别创建同类资源并互相请求列表、详情和删除
- **THEN** 每个用户只能看到和操作自己的资源，列表统计也不得泄露对方数量或内容

### Requirement: 后台任务和实时通道传递身份
队列任务、定时任务、SSE 和 WebSocket MUST 携带服务端签发的用户上下文或不可伪造的任务 owner；订阅任务进度前 MUST 校验任务归属。服务端 SHALL 禁止硬编码用户身份和接受客户端任意 user id 绑定连接。

#### Scenario: 跨用户订阅进度
- **WHEN** 用户 B 使用用户 A 的 task id 连接 SSE/WebSocket
- **THEN** 连接被拒绝或不返回事件，且不会建立跨用户订阅

#### Scenario: 后台任务完成
- **WHEN** 用户 A 的后台分析完成并产生通知
- **THEN** 结果、通知和推送只投递给用户 A 的上下文

### Requirement: 隔离审计与一致错误
越权、无效归属、管理员跨用户操作和隔离迁移 MUST 产生包含操作者、目标资源、结果和请求追踪 ID 的审计事件；对 403/404 的选择 MUST 不泄露资源存在性，且各接口错误格式保持兼容。

#### Scenario: 越权审计
- **WHEN** 用户请求不属于自己的资源
- **THEN** 系统返回受控错误并写入不可篡改语义的审计记录，不记录敏感内容
